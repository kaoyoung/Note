# [Logic Levels]([Logic Levels](https://learn.sparkfun.com/tutorials/logic-levels)) 

>[!question] 問題一
>active-low 是什麼意思？

active-low 表示 pin (腳位) 要在低電壓時才會啟動；active-high 表示 pin (腳位) 要在高電壓時才會啟動。所以平時 active-low pin 要透過上拉電阻接到 HIGH，要觸發時再拉到 GND；active-high pin 要透過下拉電阻接到 GND，要觸發時再拉到 HIGH。

>[!question] 問題二
>3.3 V 裝置的「高」和「低」各是多少伏？

![[3.3V Logic Families.png]]

從上圖較好理解:
- 輸入
	- $V_{IL}$ : 輸入電壓在 $0.8 V$ 以下，判定為 LOW
	- $V_{IH}$ : 輸入電壓在 $2.4V$ 以上，判定為 HIGH
- 輸出
	- $V_{OH}$ : 輸出為 HIGH 時保證 pin 電壓在 $2.9V$ 到 $3.3V$ 
	- $V_{OL}$ : 輸出為 LOW 時保證 pin 電壓在 $0V$ 到 $0.4V$ 

可以看到輸出比輸入更加嚴格，這是為了給雜訊留下緩衝。

>[!question] 問題三
>為什麼 Pi 的 GPIO 不能接 5 V？

GPIO (general-purpose input/output) 是 IC 或單板電腦和外界溝通的一個可程式化接腳，能依此接受外界的輸入並靠寫定的程式來和外界互動。

![[DC Charactersitic.png]]

VDD_IO 是專門供給對外收發訊號之腳位電路的電源。可以從上表的 $V_{IH}$ 的 Maximum 為 VDD_IO = 3.3V 看出 I/O 端口的最高輸入電壓為 3.3V，所以接 5V 的電壓會造成 GPIO 的損壞，因為電壓過高。從 $V_{IL}, V_{IH}, V_{OL}, V_{OH}$ 的描述可以知道
- 輸入（晶片如何判讀外部訊號）： 
	- 0V ～ 0.8V：保證判讀為 low 
	- 2.0V ～ VDD_IO：保證判讀為 high 
	- 0.8V ～ 2.0V：不確定區，可能被判讀為 low 或 high，應避免 
- 輸出（晶片的保證，預設驅動能力 8mA）： 
	- 輸出 low、灌入電流 ≤ 2mA 時：保證該腳位對 GND 的電壓 ≤ 0.4V
	- 輸出 high、拉出電流 ≤ 2mA 時：保證該腳位對 GND 的電壓 ≥ 2.9V。

>[!question] 問題三-一
>為甚麼接入電壓不用寫名電流大小，而輸出電壓要?

輸出腳不是理想電壓源，內頭有電阻，所以在電流流過時會造成電壓的下降 ($V = IR$)，因此規格書必須要註明這個電壓值是在最大多少電流下的保證。輸入腳幾乎不吃電流，漏電流 $I_{IL}$ 最大只有 $10\,\mu A$，又它本身的工作邏輯是直接比電壓大小，所以不用寫明電流大小。
# [Serial Peripheral Interface](https://learn.sparkfun.com/tutorials/serial-peripheral-interface-spi)

SPI 是 microcontrollers (MCU) 和 small peripherals (shift registers, sensors. and SD card) 溝通的 interface 。SPI 用一條獨立的 clock 線和資料線分開傳送，再透過 select 線來決定和哪個周邊溝通。簡單來說: SPI 是 synchronous 串列介面: controller 用獨立的 SCK 線送出 clock，資料跟著這個 clock 送，再用 CS 線決定要和哪個 peripheral 溝通。

>[!question] 問題一
>SPI 想解決一般的 serial port 的何種問題?

一般的 serial port (UART: Universal Asynchronous Receiver/Transmitter) 是 asynchronous 的，TX 跟 RX 沒有共用的 clock 用各自的時脈，只能依照約定的鮑率 (baud rate) 溝通，而且每次傳輸時都要多傳 start bit 跟 stop bit 來告知對方要傳數據跟傳完數據。如果沒按照規定的 baud rate 接收跟傳遞資料，會在錯誤的時間採樣導致資料亂掉。從以上描述可以看出 asynchronous 的 serial port 至少有以下三個問題
- start bit 跟 stop bit 帶來傳輸的 overhead
- transmitter 跟 receiver 的規格要能互相支援
- 接收端需要較複雜的硬體 (UART)

>[!question] 問題二
>四條線各做什麼？(SCK、POCI (MISO)、PICO (MOSI)、CS (SS))

- SCK (CLK): SPI 只有一側會產生 clock signal，這一次會叫做 controller 另一側會叫做 peripheral
- PICO (Peripheral In / Controller Out): 這是一個 data line，用來將資料從 controller 傳到 peripheral。
- POCI (Peripherail Out / Controller In): 這是一個 data line，用來將資料從 peripherial 傳到 controller。
- CS (Chip Select): 這是一個用來告訴 peripheral 啥時要接或發信號。

傳資料和收資料用不同線，所以 SPI 是 full duplex：每個 clock 都會同時送出 1 bit、收進 1 bit（見問題四）。至於兩個方向的資料能不能同時都有用（例如一邊送下一次的命令、一邊收上一次的結果），要看 datasheet。

>[!question] 問題二之一
>controller 怎麼知道 POCI 要回傳多少資料，已生成對應的 clock signal?

clock 只能由 controller 產生，peripheral 無法主動產生 clock，所以 controller 需要事先知道要多少資料，而這由 peripheral datasheet 規定
- 固定長度: 裝置固定回傳 N 個 byte，controller 送 N 個 dummy byte 把資料推出來
- 由 controller 決定: 例如: 支援連續讀取的感測器，controller 想讀多少就送多少 clock。
- 先回傳長度: 先讀 1 到 2 個 byte 的長度，再讀剩下的資料。
- 輪詢 (polling): 例如 SD card 在 SPI mode 下，controller 一直送 0xFF，直到收到 start token 才開始讀資料。

>[!question] 問題三
>CS 拉低代表什麼？

CS line 通常是處於 high 的狀態表達 disconnected，當 CS 拉低則表達 connected，這邏輯叫做 active-low。

>[!question] 問題四
>為什麼 SPI 是一邊送一邊收？

controller 和 peripheral 各有一個 shift register，PICO 和 POCI 把兩個 shift register 串成一個環。每一個 clock，controller 從 PICO 推出 1 bit，同時從 POCI 收進 1 bit；peripheral 也一樣。8 個 clock 之後，兩邊的 byte 剛好互換。所以「送」和「收」其實是**同一個動作**，不可能只送不收：
- 只想讀的時候，controller 還是要送 dummy byte 來產生 clock。
- 只想寫的時候，也一樣會收到 byte，用不到就丟掉。

>[!question] 問題五
>查一下 SPI mode 0–3 的差別?

SPI mode 主要是看兩個參數: CPOL (Clock Polarity)、CPHA (Clock Phase) 由這參數定義出四個 mode。
- CPOL
	- CPOL = 0: 表示空閒時是 low
	- CPOL = 1: 表示空閒時是 high
- CPHA
	- CPHA = 0: 第一個跳變沿採樣
	- CPHA = 1: 第二個跳變沿採樣。

>[!question] 問題一
>輸入腳沒接東西時為什麼會「浮動 (floating)」？

如果輸入腳沒接上任何東西的話，則輸入腳極容易被影響，例如: 旁邊走線的訊號耦合過來、手指靠近時的靜電等，這些干擾只會帶進極少量的電荷，但輸入腳的輸入阻抗 (Impedance) 非常大，進來的電荷幾乎流不走，也沒有任何路徑把電壓拉回固定值，所以這一點點電荷就足以讓電壓大幅改變 (電荷有正負所以有可能從 high 到 low)。結果 MCU 讀到 high 還是 low 無法確定，這就是浮動。所以這時可以透過 R1 接上一個固定的電壓 (VCC)，讓這個接腳的電壓固定成 VCC，然後接地的話電阻可以約略視為零，同時 R1 的存在避免了短路。

>[!question] 問題二
>上拉電阻太大或太小各有什麼問題？

如問題一所述，VCC 提供一個穩定的電壓，而 R1 則是負責在 bottom 接上時避免短路用的，因為如果沒 R1 則 VCC 直接接地，那會短路造成電流急遽增大。由前面的思路，我們會希望 R1 大一點，這樣接地時電流可以小一點，以避免浪費電跟電線過熱，那是越大越好嗎?
![[Pull-up resistor and MCU resistant.png]]
參考: [Pull-up Resistors](https://learn.sparkfun.com/tutorials/pull-up-resistors)

看上圖，考慮 Buttom 沒接上的狀況，VCC 到輸入腳 (input pin) 的電壓差是電流乘上 R1 得到的，又 R2 是固定的，所以 R1 不能過大，不然 input pin 跟 VCC 的電壓差會超過容忍值，常見的經驗是用 $R1 \leq \frac{R2}{10}$。另一個 R1 的影響在於，輸入腳加上走線，可以看成一個對地的小電容，輸入腳從 low 到 high 需要有電流來把它充電到 VCC，所以 R1 越大會讓電流變小，電壓上升的慢，使得腳反應變慢。
>[!note] 電容
>電容是一種能「存電荷」的結構，最簡單的樣子是兩片金屬板面對面，中間隔著絕緣物。電容存了多少電荷和電壓成正比，公式為: $Q = C \times V$
>- Q (電荷量): 代表有多少電，單位是庫倫 (C)。一庫倫有 $6.24 \times 10^{18}$ 個電子。
>- C (電容值): 代表每 1V 可以存多少電荷，單位是法拉 (F)。
>- V (電壓): 兩點之間推動電荷的壓力，單位是伏特 (V)。
# [Serial Communication](https://learn.sparkfun.com/tutorials/serial-communication)

>[!question] 問題一
>synchronous 跟 asynchronous 差別在哪? 常見的 interface 有誰?

Synchronous 至少需要兩條線來傳輸數據，data line 主要提供資料，clock line 提供 clock 讓通訊雙方有統一時脈。這實作相對簡單，常見的 infterface 有
- SPI
- $\text{I}^2 \text{C}$

Asynchronous 可以不需要一條線來專門傳輸 clock signal，但需要付出一些努力在傳輸上以避免出錯。這方式挺普遍的，導致很多人在說 serial 變是在說這個協定。常見的 interface 有
- UART (Universal Asynchronous Receiver/Transmitter)

>[!question] 問題二
>為什麼兩端鮑率 (baud rate) 要一樣？

baud rate 代表資料的傳輸速度多快，單位為 bits-per-second (bps)，這單位同時也決定 transmitter 要把 serial line 維持多長時間以供 receiver 讀值。舉例來說 baud rate 為 9600 bps 則 transmitter 需要把線維持在 high 或 low 剛好 $\frac{1}{9600}$ 秒。TX 跟 RX 的 baud rate 要維持一致，不然發送跟接收的速度不一致，會導致資料傳輸錯誤。具體來說: asynchronous 沒有共用 clock，receiver 跟 transmiter 只在 start bit 傳來的時候對齊一次，之後每個 bit 都靠自己的 clock 推算取樣時間點。baud rate 有誤差的話，取樣點會一個 bit 一個 bit 累積偏移，偏到最後幾個 bit 就會取錯值。


>[!question] 問題三
>為什麼 TX 要接對方的 RX？

TX 跟 RX 是相對於裝置本身，所以你傳的要接上對方接的 (你的 TX 接對方的 RX)，你收的要接上對方傳的 (你的 RX 接對方的 TX)。

>[!question] 問題四
>115200 8N1 是什麼意思？

從資料的架構來看
![[Pasted image 20261111111422.png]]
參考: [Serial Communication](https://learn.sparkfun.com/tutorials/serial-communication)

可以看到資料的架構總共有 4 個部分
- start bit: 只有一個 bit 用來把資料線從 idle 變為 busy
- stop bit: 可以有一個或兩個 bit，用來把資料線從 busy 變為 idle
- data chunk: 資料本身。可以是 5 到 9 個 bit。
- parity bit: 用來做 error checking，不一定需要這個 bit，通常有兩種模式
	- odd parity: data chunk + parity bit 中 bit 為 1 的數量需為奇數。
	- even parity: data chunk + parity bit 中 bit 為 1 的數量需為偶數。

資料傳輸的方式有 MSB (Most Significant bit) first 跟 LSB (Least Significant Bit) first 兩種。UART 預設的傳輸方式是 LSB first。
從 9600 8N1 來看
- baud rate: 9600 bps
- data bit: 8 bit
- N: no parity bit
- stop bit: 1 bit

依以上規格傳一個 byte 字節給對方需要 start bit + data bit + stop bit 共 1+8+1 個 bit，所以一秒鐘可以傳 $9600 \times \frac{8}{10}$ 個資料用的 bit 。
那 115200 8N1 的意思為
- baud rate: 115200 bps
- data bit: 8 bit
- N: no parity bit
- stop bit: 1 bit
# [I2C](https://learn.sparkfun.com/tutorials/i2c)

$\text{I}^2 C$ (inter-integrated Circuit) 讓多個 controller 和多個 peripheral 可以溝通，它和 SPI 一樣都是設計用來在一個裝置內短距離通訊的，和 Asynchronous Serial Interface (such as UARTs) 一樣都只需要兩條線。

>[!question] 問題一
>為什麼兩條線就能接很多裝置？

$\text{I}^2 \text{C}$ 主要有兩條線:
- SDA (Serial Data): data signal
- SCL (Serial Clock): clock signal

所有的裝置都是並聯在這一組 SDA 跟 SCL 上，每個 peripheral 都有自己的位址，controller 通訊時都要先送「位址 + R/W bit」，只有位址對得上的裝置會回 ACK、參加後面的通訊，其他裝置不理會，所以不用每個裝置都拉一條線。整體上大家都利用問題二提到的 open drain 避免掉 bus contention。

>[!question] 問題二
>為什麼 I2C 一定要上拉電阻？

I2C bus driver 是 open drain 的，代表它可以把對應的線變為 low 但不能變為 high，其原理便是把線接地，如下圖所示
![[I2C Sketch.png]]
參考: [What is the I2C Communication Protocol?](https://www.circuitbread.com/tutorials/what-is-the-i2c-communication-protocol?utm_source=chatgpt.com)

用 open-drain 而不用 push-pull，是因為 push-pull 可以主動輸出 high（接 VDD）和 low（接 GND），多個裝置共用一條線時，只要一個輸出 high、另一個輸出 low，VDD 就會直接短路到 GND。open-drain 的裝置只會「拉低」或「放開」，所以不會互相衝突，這是多個裝置能共用兩條線的前提。
而 pull-up resistor 的用途就在於當線接地時避免短路，同時 pull-up 可以讓線便 high 避免 floating。這個 open drain 的設計可以自動地做 bus arbitration，當 device 1 想傳 1 而 device 2 想傳 0 時因為整條線路接地，所以會傳 0 導致 device 1 知道自己輸了而不再傳數據，這設計又叫做 weired AND (只要有任何一個裝置拉低，整條線就是 low，0 永遠優先)。
Controller 在發起傳輸前會先檢查 bus，如果是 bus busy 變不再發起傳輸，當多個 controller 發現 bus 不是 busy 且想要傳數據變會同時發出 START，在傳輸過程中會逐 bit 檢查，值到有人輸為止 (因為 controller 會邊送邊讀回 SDA)，輸的那方退出。

>[!question] 問題三
>SPI 和 I2C 各適合什麼場合？

I2C 只用 SCL、SDA 兩條線，靠位址選裝置，增加裝置不用增加腳位，而且有 ACK 可以確認對方有回應，也支援 multi-master。但它是 open-drain 加上拉電阻，上升緣受 RC (resistor、capacitor) 限制，常見只有 100k/400 kHz，而且是半雙工。所以 **I2C 適合低速、資料量小、裝置多、腳位有限的場合**，像溫濕度感測器、EEPROM、RTC、PMIC 的暫存器設定。

SPI 是 push-pull，，輸出 high 時由內部電晶體直接接 VDD，等效電阻只有幾十 Ω，上升緣很陡，再加上全雙工且沒有位址和 ACK 的負擔，時脈可以到數十 MHz，代價是每個 slave 要多一條 CS，也沒有確認機制。所以 **SPI 適合高速、大量或連續資料的場合**，像 SPI NOR flash、SD 卡、TFT LCD、高取樣率 ADC。
