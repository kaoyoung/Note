# Agile Paging: Exceeding the Best of Nested and Shadow Paging
## Summary
This paper proposes agile paging to balance the trade-offs between shadow and nested paging. The design is motivated by two observations. First observation is that the page table is not modified uniformly: some pages are modified frequently, while the other pages are seldom modified. The second observation is that the lower-level page tables are more likely modified compared to the upper-level pages. According to these observations and shadow paging is good at dealing with TLB miss but has the difficulty modifying the page table, while nested paging is good at modifying the page table but has the difficulty dealing with TLB miss. This approach combines the nested and shadow paging. The page table is traversed starting from the shadow page table. If the page table is modified frequently, the level and all levels below that page table are moved to nested mode. The consistency between nested and shadow paging is guaranteed by switching, access, and dirty bits. The performance of agile paging is better than nested and shadow paging.
## Questions
1. Why do we assume that the guest process starts in full shadow mode in agile paging, with the exception of short-lived or small processes?
2. In agile paging, why are a specific level and all levels below it transitioned to nested mode when the VMM detects two writes within a fixed time interval? Is it possible to transition only that specific level to nested mode?
3. Why was the linear model used to predict the performance instead of implementing this technique and testing the technique directly?
# Optimizing Nested Virtualization Performance Using Direct Virtual Hardware
## Summary
Traditional nested virtualization suffers from lots of VM exits since guest hypervisor typically intercepts and emulates all operations for the nested guest VM. To address this overhead, authors develop the DVH approach that makes the host hypervisor to directly handle specifics traps from the nested guest VM, bypassing the guest hypervisor.  This reduction in the traditional nested virtualization is achieved by four core mechanisms: virtual-passthrough (which leverages the host to emulate IOMMU and I/O devices), virtual timers (which manage time differences directly within the VMCS), virtual IPIs (which route inter-processor interrupts directly using a vCPU mapping table), and virtual idle (which natively handles idle instructions).Furthermore, authors give the approach to handle recursive virtualization and live migration that make this technique more scalable and practical for real-world deployments. The performance of DVH is near native execution speed.
## Questions
1. Why does the $L_1$ virtual IOMMU rely on software-managed shadow page tables instead of multilevel hardware querying?
2. What happens in a recursive DVH setup if an intermediate hypervisor chooses to disable the virtual timer?
3. We bypass the $L_1$ hypervisor in some cases. Will this make the $L_1$ hypervisor lose control of its VM?
