# 基本事實
- 在 Linux 的系統中使用文字編輯器來編輯你的 Linux 參數設定檔，可是一件很重要的事情呦。
- 在 Linux 的世界中，絕大部分的設定檔都是以**ASCII 的純文字**形態存在，因此利用簡單的文字編輯軟體就能夠修改設定了。
---
# 動機
- **所有的 Unix Like 系統都會內建 vi 文書編輯器**，其他的文書編輯器則不一定會存在。
- 很多個別軟體的編輯介面都會主動呼叫 vi (例如未來會談到的 [crontab](https://linux.vbird.org/linux_basic/0430cron.php#crontab), [visudo](https://linux.vbird.org/linux_basic/0410accountmanager.php#visudo), [edquota](https://linux.vbird.org/linux_basic/0420quota.php#edquota) 等指令)。
- vim 具有**程式編輯的能力**，可以主動的以字體顏色辨別語法的正確性，方便程式設計。
- 因為程式簡單，**編輯速度相當快速**。

##### Q : What's the difference between **Crtl+r** and **.**
##### A : 
| 行為              | `.`               | `Ctrl+r`              |
| --------------- | ----------------- | --------------------- |
| 重複動作來源          | **上一個修改（change）** | **被 undo 的修改**        |
| 與 undo tree 的關係 | ❌ 完全無關            | ✔️ 完全**依賴 undo tree** |
| 若沒有 undo 過      | ✔️ 可用             | ❌ 無效                  |
| 用來做             | 重複剛剛的編輯           | 回到未復原的狀態              |
| 能否跨多種類動作        | ❌ 只能上一個 change    | ✔️ 依照時間順序 redo        |
#### 搜尋與取代

|                       |                                                                                                                                        |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| /word                 | 向游標之下尋找一個名稱為 word 的字串。例如要在檔案內搜尋 vbird 這個字串，就輸入 /vbird 即可！ (常用)                                                                         |

> s : substitute
> g : global in line (行內全替換)

## vim 的暫存檔、救援回復與開啟時的警告訊息
- 當我們在使用 vim 編輯時，**vim 會在與被編輯的檔案的目錄下，再建立一個名為 .filename.swp 的檔案**。
- 你對 filename 做的動作就會被記錄到這個 .filename.swp 當中喔！如果你的系統因為某些原因斷線了， 導致你編輯的檔案還沒有儲存，這個時候  .filename.swp 就能夠發揮救援的功能了
![[error in vim(E325).png]]
### 問題一 : 可能有其他人或程式同時在編輯這個檔案
可能造成race condition : 
>多個執行緒/程序同時讀寫共享資源（這裡是檔案），而缺乏足夠的同步機制，導致結果依存於執行順序。

解法 : 
- 找到另外那個程式或人員，請他將該 vim 的工作結束，然後你再繼續處理。
- 如果你只是要看該檔案的內容並不會有任何修改編輯的行為，那麼可以選擇開啟成為唯讀(O)檔案。
### 問題二 : 在前一個 vim 的環境中，可能因為某些不知名原因導致 vim 中斷 (crashed)：
這就是常見的不正常結束 vim 產生的後果。解決方案依據不同的情況而不同喔！常見的處理方法為：
- 如果你之前的 vim 處理動作尚未儲存，此時你應該要按下『R』，亦即使用 (R)ecover 的項目， 此時 vim 會載入 .man_db.conf.swp 的內容，讓你自己來決定要不要儲存！這樣就能夠救回來你之前未儲存的工作。 不過那個 .man_db.conf.swp 並不會在你結束 vim 後自動刪除，**所以你離開 vim 後還得要自行刪除 .man_db.conf.swp 才能避免每次打開這個檔案都會出現這樣的警告**。
- 如果你確定這個暫存檔是沒有用的，那麼你可以直接按下『D』刪除掉這個暫存檔
### 警告畫面的按鈕
- \[O\]pen Read-Only：打開此檔案成為唯讀檔。
- (E)dit anyway：還是用正常的方式打開你要編輯的那個檔案， **並不會載入暫存檔的內容**。不過很容易出現兩個使用者互相改變對方的檔案等問題！==不好不好==！      
- (R)ecover：就是**載入暫存檔的內容**，用在你要救回之前未儲存的工作。 不過當你救回來並且儲存離開 vim 後，還是要**手動自行刪除那個暫存檔喔**！  
- (D)elete it：你確定那個暫存檔是無用的！那麼開啟檔案前會先將這個暫存檔刪除！ 這個動作其實是比較常做的！因為你可能不確定這個暫存檔是怎麼來的，所以就刪除掉他吧！哈哈！  
- (Q)uit：按下 q 就離開 vim ，**不會進行任何動作回到命令提示字元**。  
- (A)bort：**忽略這個編輯行為，感覺上與 quit 非常類似**！會送你回到命令提示字元就是囉！
#### (Q)uit和(A)bort的差別
(Q)uit：退出 Vim 本身，不碰檔案。  
(A)bort：退出 Vim，並取消外部觸發這次編輯的動作（例如 Git commit）。

## Q2 : What's tab、windon、buffer ?
- 一個 Vim 工作階段(Vim session)會包含多個「分頁」(tab)，每個分頁中又包含多個「視窗」(window)。
- Vim會在背景中維護一份接觸過的檔案清單(Buffers)，你可以在這buffer中切換接觸過的檔案，而你可以透過window看其中一個buffer
- By default, Vim opens with a single tab, which contains a single window.
其實應該把tab跟window合在一起看，而buffer視為另一個部分。Buffers是讀到你記憶體的所有檔案，而tab跟window是你以什麼組合方式去看這些檔案(buffers)，換言之Buffers是源頭，tab跟window是外在型態。
## Q3 : How do I switch buffers in the current window?
#### Buffer 層面的操作
先看在buffers中有那些檔案
```
:ls
:buffers
```
切換目前的window到哪buffer
```
:b <檔名/編號>
```
從記憶體中移除這個檔案
```
:bd     // buffer delete
```
#### window層面的操作
水平分割出一個新 Window。
```
:sp
```
垂直分割出一個新 Window。
```
:vsp
```
在不同 Window 間移動游標。
```
Ctrl+w+方向鍵(hjkl)
```
關閉目前的 Window
```
:q
```
#### 加映 : tab層面的操作
開啟一個全新的 Tab
```
:tabnew
```
切換到下一個 Tab
```
gt
```
關閉目前的 Tab
```
:tabclose
```
## Q4 : What's the meaning of the following sentence ?
> Vim is programmable (with Vimscript and also other languages like Python), and Vim’s interface itself is a programming language

我們分段來分析
>Vim is programmable (with Vimscript and also other languages like Python)

你可以透過寫腳本來改變 Vim 的行為，或者讓它自動執行複雜的任務。你可以去`.vimrc`這個配置檔去改，使他成為你想的樣子。來到下一句話
>Vim’s interface itself is a programming language

去看vim的語法公式: **操作(Operation)+數量(Count)+範圍(Range)+動作(Motion/Object)** 
- **動詞 (Operators):** 告訴 Vim **做什麼**。    
    - `d` = Delete (刪除)        
    - `c` = Change (修改，刪除並進入輸入模式)        
    - `y` = Yank (複製)        
    - `v` = Visual (選取)        
-  **範圍(Range):** 限定名詞的範圍
	- `i` (inside) :  只操作內容，**不包含**邊界（引號、括號）或周圍的空白。
	- `a` (around) : 操作內容，**並且包含**邊界或周圍的一個空白。
- **名詞 (Objects / Motions):** 告訴 Vim **對誰做**。    
    - `w` = Word (單字)               
    - `$` = End of line (行尾)        
**例子 :**
1. `daw` : delete around word
2. `c2w` : change 2 word
3. `yi(` : yank inside parentheses
4. `d$` : Delete to the end of the line
額外的例子 : 
`ggVGy` : gg表示到檔案最前面，V表示進入行選取模式，G表示到檔案最後面，y表示複製
## Q5 : 為啥我在vim的command mode中`:2,2s/con/cut/c`只能替換一次
你寫成`:2,2s/con/cut/gc`就行，回顧command mode中取代功能的模板(參考自[Vim 的常用操作](https://bingdoal.github.io/dev-tools/2021/07/vim-usual-operation/))
> `:<range>s/<source>/<replace>/<g,c,i>`
- `g`: 代表全部取代
- `i`: 表示不分大小寫
- `c`: 在每個字段被取代前進行確認是否取代
    - `y`、`n`: 這兩個選項應該不需要解釋
    - `a`: 代表從這個之後全部同意
    - `q`: 代表從這個之後全部不同意
