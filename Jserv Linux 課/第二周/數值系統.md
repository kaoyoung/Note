# Q1: 三進位系統有何優勢?
從兩角度來解剖，第一個是儲存一個數 $N$ 需要多少空間，第二個是三進位系統和二進位系統操作比較。先思考儲存空間，假設 $E(N,b)$ 表示儲存常數 $N$ 所需付出的儲存空間，那 $$\frac{E(N, b_1)}{E(N, b_2)} = \frac{b_1 \ln_{b_1} (N)}{b_2 \ln_{b_2} (N)} = \frac{b_1 \frac{\ln(N)}{\ln(b_1)}}{b_2 \frac{\ln(N)}{\ln(b_2)}} = \frac{b_1 \ln(b_2)}{b_2 \ln(b_1)}$$ 現在因為要比較不同進位系統，所以固定在分母的 $E(N, b_2)$ 為 $E(N, e)$ ，我們因此有 $$\frac{E(N, b_1)}{E(N, b_2)}  = \frac{b_1 \ln(b_2)}{b_2 \ln(b_1)} = \frac{b_1 }{e \ln(b_1)}$$ 現在要求最小值所以看 $$\frac{\partial}{\partial b_1} (\frac{b_1 }{e \ln(b_1)}) = (e \ln(b_1))^{-1} - b_1 (e \ln(b_1)) ^{-2} e \frac{1}{b_1} = 0 \Rightarrow  e \ln(b_1) - e  = 0 \Rightarrow \ln(b_1) = 1$$所以在 $b_1 = e$ 時有極值; 另一方面 $$\frac{\partial}{\partial b_1} \ln (b_1) = \frac{1}{b_1} > 0$$ 代表以 $e$ 為進位系統的存儲空間最小。而在現實世界中我們造不出 $e$ 進位系統，因為他是無理數，而在整數中在 $\frac{b_1 }{e \ln(b_1)}$ 帶入 $b_1 = 3$ 時最接近最小儲存空間。
>[!note] 
>一個 $b$ 進位系統，如果 $b$ 越大，那它所需的位元數越少，但代價是一個位元所需儲存的空間越大。觀察不難發現位元所需儲存的空間跟 $b$ 成正比，但所需的位元數跟 $\log_{b_1} (N)$ 成正比，所以一個合適的進位系統， $b$ 值不可能太大。

依照上面的思路，最優的是 $b$ 取 3 ，而次優的是取 2 跟 4 ，這邊不考慮 4 進位系統，所以我們對於三進位系統和二進位系統操作做比較。先想一下三進位給了我們什麼優勢，一個位元可以表達成正的、沒有跟負的三種狀態，所以可以很自然的定義 balanced ternary 的表達為$$b = \sum^{n-1}_{i=1} 3^i b_i, \text{ where } b_i = 1,0,-1$$ 這樣定義有幾個好處
- 零定義唯一。
- 正負號轉換，只要把 $a_i$ 乘上 $-1$ 即可。
比較三進位和二進位差別
- 二進位正負號轉換: 要先把每個位元翻轉再加一。
- 三進位正負號轉換: 要先把每個位元乘上 $-1$ 即可。
**三進位正負號轉換少做一次加一。**
>[!note] 
>二進位只能表達正的跟沒有兩個狀態，為何不用正的跟負的兩個狀態，這問題待會討論，而為了表達負數，我們只能很彆扭的把最大的位元定義為 $-2^{k-1}$，這讓我們在做正負號轉號需要把每個位元翻轉再加一，不若三進位時絲滑。

void xorSwap(int *x, int *y) {
    if(x == y) return;

5. 省去迴圈 ?
考慮以下這程式
```c
int func(unsigned int x) {
    int val = 0; int i = 0;
    for (i = 0; i < 32; i++) {
        val = (val << 1) | (x & 0x1);
        x >>= 1;
    }
    return val;
}
```
這段程式的作用是逐位元反轉順序，顛倒後位元不足 32bit 者，全部補 0。可以用 bitwise operation 代替 for 迴圈
```c
new = num;
new = ((new & 0xffff0000) >> 16) | ((new & 0x0000ffff) << 16);
new = ((new & 0xff00ff00) >> 8) | ((new & 0x00ff00ff) << 8);
new = ((new & 0xf0f0f0f0) >> 4) | ((new & 0x0f0f0f0f) << 4);
new = ((new & 0xcccccccc) >> 2) | ((new & 0x33333333) << 2);
new = ((new & 0xaaaaaaaa) >> 1) | ((new & 0x55555555) << 1);
```
具體想法是從大塊到小塊依序翻轉。
