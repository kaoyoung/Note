## 一、選擇題詳解

### 1. 答案：(C) `0x0A`

```
  0101 1010   (0x5A)
& 0000 1111   (0x0F)
-----------
  0000 1010   (0x0A)
```

`& 0x0F` 就是「只留下低 4 個 bit」，這種遮罩很常用。

### 2. 答案：(A) `0xA5`

```
  0101 1010   (0x5A)
^ 1111 1111   (0xFF)
-----------
  1010 0101   (0xA5)
```

跟 1 做 XOR 會反轉該 bit，所以 `^ 0xFF` 等於反轉全部 8 個 bit。

### 3. 答案：(D) `x &= ~(1 << 3);`

`~(1 << 3)` 是「除了 bit 3 以外全部是 1」的遮罩，AND 上去就只會清掉 bit 3。

- (A) 會把 bit 3 以外的 bit 全部清掉。
- (B) 是反轉（toggle），原本是 0 的話會變成 1。
- (C) 幾乎會把所有 bit 都設成 1。

### 4. 答案：(B)

`==` 的優先順序**高於** `&`，所以實際上是 `x & (0x04 == 0)` → `x & 0` → 永遠是 0。這是非常經典的 bug，gcc 開 `-Wall` 會警告。

正確寫法：`if ((x & 0x04) == 0)`。**位元運算一律加括號。**

### 5. 答案：(C)

`1` 的型別是有號 `int`，`1 << 31` 的結果超出 `int` 能表示的範圍，在 C 裡是 undefined behavior。實務上常常「剛好」得到 `0x80000000`，但不能依賴。

正確寫法：`1u << 31` 或 `1UL << 31`。另外，位移量大於等於型別的位元數（例如 32-bit 的值 `<< 32`）也是 UB。

### 6. 答案：(A)

`x - 1` 會把最低位的 1 變成 0，並把它右邊的 0 全部變成 1；再跟 `x` 做 AND，就只清掉了最低位的那個 1。

```
x       = 1011 0110
x - 1   = 1011 0101
x&(x-1) = 1011 0100
```

這個技巧用在第 22 題（數 1 的個數）和第 23 題（判斷 2 的次方）。

### 7. 答案：(D)

對負數做右移，在 C 標準裡是 implementation-defined，結果由編譯器決定。gcc、clang 都做**算術右移**（補符號位元），所以得到 -4。

需要可攜的位元操作時，應該用 `unsigned` 型別。

### 8. 答案：(B) no

**整數提升（integer promotion）陷阱**：`a` 在運算前會先被提升成 `int`，也就是 `0x0000000F`；`~` 之後變成 `0xFFFFFFF0`（-16），跟 `0xF0`（240）比較當然不相等。

正確寫法：`if ((uint8_t)~a == 0xF0)`。

同樣的陷阱也出現在左移：`uint8_t` 做 `<< 2` 時，結果是 `int`，高位不會被截掉，要等到存回 `uint8_t` 時才會截掉。

### 9. 答案：(C) 0

`p` 和 `q` 指向同一個變數時，第一行 `*p ^= *q` 就等於 `a ^= a`，直接變成 0，後面兩行也都是 0。

XOR swap 是面試常考的技巧，但實務上不建議使用：除了這個陷阱，現代編譯器對「用暫存變數交換」最佳化得一樣好，而且更好讀。

### 10. 答案：(B) 78

little-endian 把**最低位的 byte** 放在最低的位址：

```
位址：  p[0]  p[1]  p[2]  p[3]
內容：   78    56    34    12
```

big-endian 則相反，`p[0]` 會是 12。網路傳輸（network byte order）用的是 big-endian，所以設備做網路通訊時常要轉換（見第 25 題）。

## 二、計算題詳解

```c
uint8_t a = 0xB6;   /* 1011 0110 */
uint8_t b = 0x5C;   /* 0101 1100 */
```

| 題號 | 運算 | 二進位 | 十六進位 |
|---|---|---|---|
| 11 | `a & b` | 0001 0100 | `0x14` |
| 12 | `a \| b` | 1111 1110 | `0xFE` |
| 13 | `a ^ b` | 1110 1010 | `0xEA` |
| 14 | `~a` | 0100 1001 | `0x49` |
| 15 | `a << 2` | 1101 1000 | `0xD8` |
| 16 | `a >> 3` | 0001 0110 | `0x16` |
| 17 | `a & ~b` | 1010 0010 | `0xA2` |
| 18 | `a & (a - 1)` | 1011 0100 | `0xB4` |
| 19 | `a & (-a)` | 0000 0010 | `0x02` |
| 20 | `(a >> 4) & 0x0F` | 0000 1011 | `0x0B` |

**容易錯的題目：**

- **14**：完整結果其實是 `int` 的 `0xFFFFFF49`（見選擇題第 8 題），取最低 8 bits 才是 `0x49`。
- **15**：`1011 0110` 左移 2 位是 `10 1101 1000`，超出 8 bits 的部分被截掉。
- **17**：`a & ~b` 的意思是「把 `b` 中是 1 的位置，從 `a` 裡清掉」，在暫存器操作很常用。
- **18**：清掉最低位的 1（見選擇題第 6 題）。
- **19**：`x & (-x)` 會**只留下**最低位的 1。因為 `-x` 等於 `~x + 1`：`~a` 是 `0100 1001`，加 1 是 `0100 1010`，跟 `a` 做 AND 得到 `0000 0010`。
- **20**：取出高 4 個 bit（high nibble），這就是「取出欄位」的標準寫法。

## 三、程式題詳解

### 21. 位元操作巨集

```c
#define SET_BIT(x, n)     ((x) |=  (1u << (n)))
#define CLEAR_BIT(x, n)   ((x) &= ~(1u << (n)))
#define TOGGLE_BIT(x, n)  ((x) ^=  (1u << (n)))
#define READ_BIT(x, n)    (((x) >> (n)) & 1u)
```

**評分重點**（每個巨集 2 分）：

- 參數和整個運算式都要加括號，否則像 `SET_BIT(reg, i + 1)` 這種用法會因為優先順序出錯。
- 用 `1u`，避免 `n = 31` 時的 undefined behavior（選擇題第 5 題）。
- `READ_BIT` 寫成 `((x) & (1u << (n)))` 的話，結果是 0 或 2ⁿ，不符合「0 或 1」的要求，扣 1 分。

### 22. 計算 1 的個數

**解法一：利用 `x & (x - 1)`**（推薦，迴圈次數 = 1 的個數）

```c
int count_ones(uint32_t x) {
    int count = 0;
    while (x) {
        x &= x - 1;   /* 每次清掉最低位的 1 */
        count++;
    }
    return count;
}
```

**解法二：逐一檢查**（固定跑 32 次以內）

```c
int count_ones(uint32_t x) {
    int count = 0;
    while (x) {
        count += x & 1u;
        x >>= 1;
    }
    return count;
}
```

**評分重點**：任一解法正確即得 8 分。參數必須是無號型別：如果用 `int` 加右移，負數會一直補 1，變成無窮迴圈。

**補充**：gcc／clang 有內建的 `__builtin_popcount(x)`，面試時提到可以加分。

### 23. 判斷 2 的次方

```c
#include <stdbool.h>

bool is_power_of_two(uint32_t x) {
    return x != 0 && (x & (x - 1)) == 0;
}
```

2 的次方的二進位**只有一個 1**，清掉它之後就會變成 0。

**評分重點**：忘記處理 `x == 0`（0 會被誤判為 true）扣 3 分；`&` 運算沒加括號扣 2 分（選擇題第 4 題的陷阱）。

### 24. 暫存器欄位操作

```c
#define MODE_SHIFT  8
#define MODE_MASK   (0xFu << MODE_SHIFT)   /* 0x00000F00 */

/* (a) 讀出 MODE */
uint32_t mode = (CTRL & MODE_MASK) >> MODE_SHIFT;

/* (b) 設定 MODE：先清掉舊值，再放入新值 */
CTRL = (CTRL & ~MODE_MASK) | ((val << MODE_SHIFT) & MODE_MASK);
```

**評分重點**：

- (a) 3 分：遮罩和位移都要有（也可以寫成 `(CTRL >> 8) & 0xF`）。
- (b) 5 分：一定要**先清再設**。只寫 `CTRL |= val << 8` 的話，舊的 1 清不掉，只得 1 分。
- `val` 也要做遮罩：萬一 `val` 超過 15，才不會蓋到別的欄位。

**加分**：能提到「讀出、修改、寫回（read-modify-write）不是 atomic，如果 ISR 也會改 `CTRL`，要先關中斷或用其他保護機制」，就是有實務經驗的回答。

### 25. 位元組順序轉換

```c
uint32_t swap_bytes(uint32_t x) {
    return ((x & 0x000000FFu) << 24) |
           ((x & 0x0000FF00u) <<  8) |
           ((x & 0x00FF0000u) >>  8) |
           ((x & 0xFF000000u) >> 24);
}
```

每個 byte 先用遮罩取出來，再移到對應的位置，最後用 OR 組合起來。

**評分重點**：四個 byte 各 2 分。遮罩可以先做也可以後做，例如 `(x >> 8) & 0x0000FF00u` 也對。

**補充**：gcc／clang 有 `__builtin_bswap32(x)`；網路程式通常用 `htonl()`／`ntohl()`。
