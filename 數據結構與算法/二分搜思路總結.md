# 概覽
二分搜的核心概念在於快速地刪除一大批不可能的區域，使得搜索空間快速變小，最後可能搜索空間大小歸零表沒有解，或是在搜索空間剩一個時符合要求即為所求。這邊可以看到二分搜關注的點在於刪除條件，由刪除條件來得知下一輪的搜索空間為何。~~本篇以二分搜常見的 left 跟 right 指針來探討兩個常見解題思路~~
1. ~~left 跟 right 單純框出可能解區域。~~
2. ~~left 先定義出一個不變量，right 取這不變量的相反，最後 left 即為所求。~~

上述兩思路都不夠完整，都只是二分搜進程的一個面向。二分搜可以分為三個步驟:
1. 確認搜尋空間
2. 刪除邏輯
3. 何時停下

第二步正是前所述的「left 跟 right 單純框出可能解區域」的核心邏輯，第三步可以藉由「left 跟 right 所代表的不變量」來協助判定，或是直接說該刪的都刪了，剩下的幾個解直接判斷即可，或是說解一定在原本搜尋空間中，又現在只剩一個解那他一定是答案。

# 思路探討
## [34. Find First and Last Position of Element in Sorted Array](https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/)

這題需要給出兩個下標位置，分別是「第一個出現該數字的位置」跟「最後一個出現該數字的位置」。一個做法是為這兩位置寫不同的流程去處理。我想用一個統一的函式 (`f`) 去找這兩位置，這函數應該是在給定一數值 (`x`) 後返回第一個比他大的數值所在位置，如果該數大於等於數組中所有數值，那返回 `n`。首先思考搜尋範圍為何，從一開始到最後一個位置加一皆有可能是所求，所以搜尋範圍是 $[0, n]$ 。刪除的邏輯要依照 `nums[middle]` 跟 `x` 的大小關係來處理:
- `nums[middle] < x`: middle 以下的所有位置皆不可能是解，所以 `left = middle + 1`。
- `nums[middle] == x`: middle 以下的所有位置皆不可能是解，所以 `left = middle + 1`。
- `nums[middle] > x`: 超過 middle 的所有位置皆不可能是解，所以 `right = middle`。

刪除邏輯告訴我們: 「left 之前和 right 之後的位置皆不可能是解，所以 `left==right` 時即為所求」。至於是否會停下看下一題的說明。有 `f` 之後讓 `x` 分別帶入 target-1 跟 target，分別得到解 $a_1$ 跟 $a_2$，我們只要確認 $a_1 < n$ 且 $nums[a_1] == target$ 即可知有找到解，那 $a_1$ 跟 $a_2-1$ 即為所求

## [35. Search Insert Position](https://leetcode.com/problems/search-insert-position/)

首先思考搜尋範圍為何，從一開始到最後一個位置加一皆有可能是插入的位置，所以搜尋範圍是 $[0, n]$ 。刪除的邏輯要依照 `nums[middle]` 跟 `target` 的大小關係來處理:
- `nums[middle] < target`: middle 以下的所有位置皆不可能是解，所以 `left = middle + 1`。
- `nums[middle] == target`: middle 即為所求，所以 `return middle`。
- `nums[middle] > target`: 超過 middle 的所有位置皆不可能是解，所以 `right = middle`。

刪除邏輯告訴我們: 「left 之前和 right 之後的位置皆不可能是解，所以 `left==right` 時即為所求」。至於是否會停下，由於 `middle = left + (right - left)/2` 因此在 $left < right$ 時
$$
left \leq middle < right
$$
又 `left = middle + 1` 且 `right = middle`，可只區間有變小，所以不可能無限迴圈。

## [153. Find Minimum in Rotated Sorted Array](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/)

首先思考搜尋範圍為何，從一開始到最後一個位置皆有可能是最小值所在位置，所以搜尋範圍是 $[0, n-1]$ 。刪除的邏輯要依照「搜索空間的型態」和 「`nums[middle]` 跟 `nums[left]` 的大小關係」來處理:
- 如果當前 nums 是 rotated 過的: 
	- `nums[middle] > nums[left]`: middle 以下的所有位置都不可能是解，所以 `left = middle+1`。
	- `nums[middle] == nums[left]`: 這時只剩下兩個可能值 left 和 right，又 nums 是 rotated 過的，所以直接 `left = middle+1`。
	- `nums[middle] < nums[left]`: 超過 middle 的所有位置都不可能是解，所以 `right = middle`。
- 如果當前 nums 是沒 rotated 過的: 直接回傳 `nums[left]`。

刪除邏輯告訴我們: 「left 之前和 right 之後的位置皆不可能是解，所以 `left==right` 時即為所求」。是否會停下，推倒類似上一題。

# 思路拓展
## [240. Search a 2D Matrix II](https://leetcode.com/problems/search-a-2d-matrix-ii/)

這題不像之前的題目有很好的單調性質，只在 row 跟 colum 上有其單調性質。一個顯然思路是逐行(列)去看，依此用行(列)本身的性質來二分搜找解，但這樣做只用了一半的性質。另一個想法是找頭尾之間的某一個點。找正中間那個點 (`nums[middle][middle]`) 好嗎? 如果 target 大於 `nums[midRow][midCol]` 那 `nums[midRow][midCol]` 左上的點確實可以刪掉，剩下的搜尋空間如何表達? 如何從剩下的搜尋空間找中間某一個點? 這兩問題很難回答；如果 target 小於 `nums[midRow][midCol]` 那 `nums[midRow][midCol]` 右下的點確實可以刪掉，依舊有搜尋空間跟找中間點的問題要回答。

>[!Note] 刪除邏輯的選擇
>刪除邏輯應該要簡明，應該讓勾勒搜尋範圍的參數在移動時固定一個方向，不要跳來跳去。

對於這題可以觀察到左上角跟右下角分別代表最小值和最大值，那右上或是左下角呢? 我們這邊關注於右上角，左下角用類似論證即可。一樣論證右上角的值 ($x$) 跟 target 的關係
- $x < target$: 最上面那 row 不可能是解，row 範圍減一。
- $x == target$: 回傳 `true`。
- $x > target$: 最右邊那 column 不可能是解，column 範圍減一。

## [4. Median of Two Sorted Arrays](https://leetcode.com/problems/median-of-two-sorted-arrays/)

這題有一個關鍵洞察: 「你在 nums1 切的位置可以直接推出在 nums2 上要切在哪裡，這邊切線表達數值的分界線，左邊的數值小於等於右邊的數值，因為要求的是 median，所以在切線左邊的元素個數是固定的」。我們用 `nums1_left, nums1_right, nums2_left, nums2_right` 分別表達 nums1 跟 nums2 在切線左邊跟右邊的元素，主要在 nums1 找切線 nums2 上的用推的便可以推出來，這邊有一個程式優化小技巧，先把 nums1 跟 nums2 調成 nums2.size 大於等於 nums1.size 這樣 nums2 對應的切線就只會出現在 $[0, nums2.size]$ 之間可以小一些特判。最後寫程式時可以對 `nums1_left, nums1_right, nums2_left, nums2_right` 設定特殊值以減少特判。
